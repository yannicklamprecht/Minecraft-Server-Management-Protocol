# Configuration Reference

Every server is configured by name under `minecraft.management.servers.<id>.*` - there is no
single-server shorthand, only the map. The id is an arbitrary short string of your choosing; it's
used throughout the API (`registry.session(id)`) and stamped onto every published event
(`event.getServerId()`).

| Property | Type | Default | Description |
|---|---|---|---|
| `minecraft.management.servers.<id>.url` | `URI` | `ws://localhost:25585` | The MSMP WebSocket URL. |
| `minecraft.management.servers.<id>.secret` | `String` | *(none - required)* | Bearer secret sent as the WebSocket connection's `Authorization` header. Startup fails with a clear message naming the missing property if this is absent for a configured server. |
| `minecraft.management.servers.<id>.protocol-version` | `String` | *(auto-detected)* | The MSMP protocol version to speak. Leave unset to auto-detect (see below), or pin one explicitly to skip that round-trip. |
| `minecraft.management.servers.<id>.auto-connect` | `boolean` | `true` | Whether to connect this server automatically on application startup. Set `false` for a server you want to connect to manually/only under test control. |

## Multiple servers

Just add more entries to the map:

```yaml
minecraft:
  management:
    servers:
      survival:
        url: ws://localhost:25585
        secret: ${SURVIVAL_SECRET}
      creative:
        url: ws://localhost:25586
        secret: ${CREATIVE_SECRET}
        protocol-version: 3.1.0
```

Every configured server gets its own `MinecraftManagementClient`/`MinecraftManagementSession` pair,
its own WebSocket connection, and its own independent set of published events (always
distinguishable via `event.getServerId()`). A connection failure for one server is logged and does
not stop the others from connecting, nor does it fail application startup - see
[api-guide.md](api-guide.md#resilience) for what that means for calls made against it.

## Protocol version auto-detection

There's no MSMP method to ask a server "what protocol version are you speaking" directly. Left
unset (the default), each server's actual protocol version is detected right after connecting
instead of being assumed: the client calls `minecraft:server/status` (supported by every protocol
version), reads `version.name` (the Minecraft version the server reports, e.g. `"1.21.11"`), and
maps that through a table generated by the [gradle plugin](../gradle-plugin/generated-code.md#protocolversions---the-minecraft-version-to-protocol-version-map)
straight from the real protocol schemas - so picking up newer Minecraft/protocol versions is just
a matter of regenerating the client, not updating a hand-maintained mapping here.

A Minecraft version the table doesn't recognize (older than the client was generated for, or newer
than the last time it was regenerated) falls back to the latest known protocol version, logged as
a warning rather than failing the connection.

Set `protocol-version` explicitly on a server to skip this detection round-trip entirely, or to
pin a specific version regardless of what the server reports.

## Overriding the default `ActivityRepository`

The starter registers an in-memory `ActivityRepository` via `@ConditionalOnMissingBean`. Supply
your own bean of that type (e.g. backed by a database, or with a different retention size) to
replace it:

```java
@Bean
ActivityRepository activityRepository() {
    return new InMemoryActivityRepository(2000); // e.g. just a larger in-memory history
}
```

See [events.md](events.md#activityrepository) for the interface and what it's for.
